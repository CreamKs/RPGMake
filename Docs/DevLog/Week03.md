## 2. 작업용 테스트 장면

기존 테스트 장면을 복제해 타일맵 작업용 장면을 준비했습니다.

플레이어, 몬스터, 카메라와 전투 관련 오브젝트를 그대로 가져와, 지형을 바꾸는 과정에서 이미 동작하던 기능도 함께 확인할 수 있도록 했습니다. 사망 후 현재 장면을 다시 불러오는 코드가 있으므로 새 장면도 빌드 씬 목록에 등록했습니다.

## 3. Tilemap으로 지형 만들기

테스트용 풀과 흙 바닥 이미지를 AI로 생성하고, Tile Palette에 등록해 직접 지형을 그렸습니다.

Grid는 타일을 배치할 격자를 담당하고, 자식 GroundTilemap에는 실제 바닥 타일을 배치했습니다. 타일 이미지는 한 장을 한 칸에 사용하는 방식으로 구성했습니다.

처음에는 타일을 그려도 충돌 영역이 없기 때문에 캐릭터가 밟을 수 없었습니다. GroundTilemap에 다음 컴포넌트를 추가했습니다.

| 컴포넌트 | 역할 |
| --- | --- |
| Tilemap Collider 2D | 배치한 타일의 충돌 영역 생성 |
| Rigidbody 2D | Static으로 설정해 움직이지 않는 지형으로 사용 |
| Composite Collider 2D | 인접한 타일의 충돌 영역을 하나로 합성 |

Tilemap Collider 2D의 Composite Operation은 Merge, Composite Collider 2D의 Geometry Type은 Polygons로 설정했습니다.

GroundTilemap은 기존 Ground 레이어를 사용하고, PlayerController의 지면 판정에서도 같은 레이어를 검사하도록 연결했습니다. 기존 사각형 바닥은 비활성화한 뒤 새 타일 바닥에서 이동과 착지를 확인했습니다.

## 4. 기존 원웨이 플랫폼 검증

통과형 발판과 아래 점프는 1주차에 이미 구현했기 때문에 기존 Platform 오브젝트를 유지했습니다.

타일맵으로 만든 일반 바닥과 기존 원웨이 플랫폼을 함께 배치한 상태에서 다음 동작을 확인했습니다.

- 발판 아래에서 점프해 위로 통과
- 위에서 내려올 때 발판에 착지
- 높이가 다른 발판 사이 이동
- 발판 가장자리에서 점프
- ↓ + Alt로 현재 발판을 통과
- 위 발판에서 내려온 뒤 아래 발판에 착지

일반 지형을 그리는 GroundTilemap과 통과형 발판의 충돌 규칙을 구분해 사용했습니다.

## 5. 카메라 경계와 화면 크기 확인

기존 CameraFollow의 SmoothDamp 추적, 맵 경계 제한과 Vertical Dead Zone을 유지하면서 새 테스트 맵에서 움직임을 확인했습니다.

확인 과정에서 카메라가 맵 전체를 따라가지 않고 중앙 부근에서만 움직이는 것처럼 보였습니다. 카메라 이동 한계를 로그로 출력해 보니, 실제 Camera Size가 5이고 화면 비율이 약 1.98인 상태였습니다.

현재 코드는 화면의 절반 너비를 고려해 카메라 중심의 이동 범위를 계산합니다.

~~~csharp
float cameraHalfWidth = cam.orthographicSize * cam.aspect;

float minX = mapMinX + cameraHalfWidth;
float maxX = mapMaxX - cameraHalfWidth;
~~~

맵의 X 경계가 -10부터 10까지일 때 화면의 절반 너비도 거의 10이 되어, 카메라 중심이 이동할 수 있는 범위는 약 -0.09부터 0.09까지였습니다.

이 과정을 통해 맵의 경계, 카메라 중심의 이동 한계, 한 화면에 보이는 넓이가 서로 다른 값이라는 점을 확인했습니다.

또한 게임 창의 Scale이 올라가 있어 화면이 실제보다 확대되어 보이는 문제도 있었습니다. 게임 창의 표시 배율과 Camera Size를 구분해 확인한 뒤, 원하는 시야와 카메라 추적 상태를 맞췄습니다.

Vertical Dead Zone도 화면 크기와 함께 점검해 높은 발판에서도 플레이어가 화면 안에 보이는지 확인했습니다.

## 6. Pixel Perfect Camera

플레이어와 몬스터 원본 이미지의 Filter Mode를 Point, Compression을 None으로 설정했습니다.

Main Camera에는 Pixel Perfect Camera를 적용하고, 캐릭터의 픽셀 기준과 기준 해상도를 설정했습니다. 프레임 자르기는 Windowbox, 격자 스냅은 Pixel Snapping을 사용했습니다.

Windowbox를 적용한 뒤 화면 주변에 검은 여백이 생겼지만, 이는 도트를 일정한 배율로 표시하기 위한 동작임을 확인했습니다. 실제 이동 중에도 캐릭터 표시와 카메라 추적이 정상적으로 동작했습니다.

현재 바닥은 테스트용 이미지이며, 본편 리소스를 정할 때 타일 규격과 그래픽의 픽셀 기준도 함께 정리할 예정입니다.

## 7. 공격 중 피격 후 공격이 막히는 문제

**문제**

공격 중 몬스터에게 맞으면 공격 애니메이션이 피격 애니메이션으로 전환되었습니다. 이때 공격 마지막의 EndAttack 이벤트가 실행되지 않아 isAttacking이 true로 남았고, 이후 공격 입력이 계속 차단되었습니다.

**해결**

PlayerController에 현재 공격 상태를 읽을 수 있는 IsAttacking 속성을 추가했습니다.

~~~csharp
public bool IsAttacking => isAttacking;
~~~

PlayerHealth에서는 공격 중일 때 Hit 트리거를 보내지 않도록 조건을 변경했습니다.

~~~csharp
else if (animator != null &&
         (playerController == null || !playerController.IsAttacking))
{
    animator.SetTrigger("Hit");
}
~~~

피해와 넉백은 그대로 적용하면서 진행 중인 공격은 끝까지 유지하도록 했습니다. 공격이 끝나면 기존 EndAttack 이벤트가 상태를 해제해 다음 공격을 받을 수 있습니다. 체력이 0이 된 경우에는 기존 사망 처리가 우선하도록 유지했습니다.

수정 후 공격 중 피격되어도 다시 공격할 수 있음을 확인했습니다.
