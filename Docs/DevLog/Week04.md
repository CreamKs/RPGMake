## 2. 플레이어 프리팹

씬에 배치되어 있던 Player 전체를 프리팹으로 저장했습니다.

기존에 사용하던 Visual, AttackPoint와 GroundCheck를 함께 저장해, 캐릭터 그림과 애니메이션뿐 아니라 공격 위치와 지면 판정 위치도 같은 구조로 유지했습니다.

PlayerController, PlayerCombat과 PlayerHealth의 역할도 그대로 두었습니다. 프리팹으로 만드는 과정에서 이동이나 공격 코드를 새로 작성하지 않고, 기존 Inspector 연결이 유지되는지 확인했습니다.

씬의 Player가 프리팹 인스턴스로 바뀐 뒤에도 이동, 점프, 공격과 카메라 추적이 정상적으로 동작했습니다.

### 배운 점

프리팹은 오브젝트를 단순히 복사해 두는 것보다, 컴포넌트와 자식 구조를 하나의 재사용 가능한 에셋으로 관리하는 방식이라는 점을 확인했습니다. Unreal에서 설정한 액터를 여러 곳에 배치하던 경험과 비교하면서 구조를 이해할 수 있었습니다.

## 3. 몬스터 프리팹과 추적 대상 연결

몬스터도 부모 Enemy를 기준으로 Visual, 접촉 센서와 데미지 표시 위치를 함께 프리팹으로 저장했습니다.

이때 기존 씬에서 연결했던 Player 참조를 그대로 사용할 수 있는지 확인했습니다. 프리팹 에셋은 특정 씬의 오브젝트 참조를 저장할 수 없으므로, 새로 배치한 몬스터가 실행할 때 플레이어를 찾도록 EnemyAI에 Start 처리를 추가했습니다.

~~~csharp
private void Start()
{
    if (target != null)
    {
        return;
    }

    PlayerController player =
        FindFirstObjectByType<PlayerController>();

    if (player != null)
    {
        target = player.transform;
    }
    else
    {
        Debug.LogWarning(
            "몬스터가 추적할 플레이어를 찾지 못했습니다.",
            this
        );
    }
}
~~~

이미 연결한 대상이 있으면 유지하고, 대상이 비어 있을 때만 활성 플레이어를 찾아 연결합니다. 검색은 매 프레임 반복하지 않고 몬스터가 동작을 시작할 때 한 번만 실행하도록 했습니다.

이 방식은 현재처럼 활성 플레이어가 한 명인 테스트 장면을 기준으로 사용했습니다.

프리팹 내부에서 연결할 수 있는 Visual과 데미지 표시 위치는 자식 참조를 유지하고, DamagePopup은 기존 프리팹 에셋을 연결했습니다.

## 4. 새 몬스터 배치와 회전 고정

프로젝트 창의 몬스터 프리팹을 씬에 새로 배치해, 기존 몬스터의 씬 참조 없이도 동작하는지 확인했습니다.

새 몬스터는 플레이어를 추적했고, 접촉 피해, 피격 색 변화, 데미지 숫자, 넉백과 처치도 정상적으로 동작했습니다.

3주차 작업 중에는 몬스터가 벽과 부딪힐 때 몸체가 기울어지는 현상도 확인했습니다. 몬스터 본체의 Rigidbody2D에서 Z 회전을 고정하는 설정을 적용했으며, 프리팹에서도 이 설정을 확인했습니다.

그림의 좌우 방향 전환은 계속 Visual의 X 스케일로 처리하고, 물리 몸체의 회전은 고정하는 방식으로 구분했습니다.

## 5. 첫 Windows 테스트 빌드

Unity의 빌드 프로필에서 Windows 플랫폼을 선택하고 테스트 빌드를 만들었습니다.

시작 장면은 현재 작업한 타일맵 테스트 맵으로 지정했습니다. 에디터에서 열어 둔 장면과 실행 파일에서 처음 열리는 장면이 같도록 빌드 씬 목록을 확인했습니다.

빌드 후에는 생성된 실행 파일을 직접 실행해 조작과 전투를 확인했습니다. 에디터에서만 동작하는 상태를 넘어, 별도 프로그램으로 실행되는 첫 프로토타입을 남겼습니다.

## 6. 실행 파일 검증

프리팹 적용 후 에디터에서 확인한 기능을 Windows 실행 파일에서도 직접 플레이하며 확인했습니다.

| 항목 | 확인한 내용 |
| --- | --- |
| 기본 조작 | 좌우 이동, 점프와 착지 |
| 원웨이 플랫폼 | 아래에서 통과, 위에서 착지와 아래 점프 |
| 몬스터 | 플레이어 추적, 접촉 피해와 피격 반응 |
| 공격 | 기본 공격, 데미지 숫자, 넉백과 처치 |
| 플레이어 피격 | 체력 감소와 무적 시간 |
| 공격 중 피격 | 진행 중인 공격 유지 및 다음 공격 가능 |
| 플레이어 사망 | 조작과 공격 판정 중단 |
| 장면 재시작 | 사망 후 현재 맵을 다시 불러오고 전투 재개 |
| 카메라 | 추적과 Pixel Perfect 표시 |

검증은 개발자가 직접 실행하고 플레이한 결과입니다. 현재 재시작은 저장된 진행 상태를 복원하는 기능이 아니라 테스트 장면 전체를 다시 불러오는 방식입니다.

## 7. Week 04 결과

플레이어와 몬스터를 프리팹으로 정리하고, 새로 배치한 몬스터의 추적 대상도 실행 시 연결할 수 있게 했습니다. 기존 조작과 전투를 유지한 상태로 Windows 실행 파일까지 만들어 확인했습니다.

3주차 일정이 밀렸지만, 타일맵 검증을 마친 뒤 프리팹과 빌드를 정리하는 순서는 유지했습니다. 이번 작업으로 첫 달의 기본 조작과 상호 전투 프로토타입을 실행 가능한 형태로 마무리했습니다.

아직 스킬, 성장과 저장 시스템을 갖춘 본편은 아니지만, 이후 기능을 추가하면서 비교할 수 있는 테스트 맵과 실행 빌드를 마련했습니다.
